### **1. Amazon EC2 (Elastic Compute Cloud) 핵심**
*   **개념**: AWS에서 제공하는 개별 가상 서버(인스턴스) 서비스입니다.
*   **인스턴스 상태**: 
    *   **Running**: 실행 중.
    *   **Stopped**: 중지됨 (데이터 유지, 인스턴스 유형 변경 가능).
    *   **Terminated**: 종료됨 (영구 삭제, 복구 불가).
*   **키페어 (Key Pair)**:
    *   **PEM (.pem)**: Linux, macOS의 `ssh` 명령용.
    *   **PPK (.ppk)**: Windows의 **PuTTY**용 (PuTTYgen으로 PEM을 변환하여 생성).
*   **인스턴스 프로파일 (IAM 역할)**: 인스턴스가 별도의 액세스 키 없이 S3 등 다른 서비스에 안전하게 접근할 수 있도록 권한을 대행하는 설정입니다.
*   **UserData**: 인스턴스 시작 시 자동으로 실행되는 스크립트로, 웹 서버 설치(`httpd`)나 S3 파일 복사 등에 활용됩니다.

### **2. Amazon S3 (Simple Storage Service) 핵심**
*   **개념**: 무제한 용량의 객체 기반 스토리지 서비스입니다.
*   **구성 요소**:
    *   **버킷 (Bucket)**: 저장 공간의 최상위 단위이며, 전 세계에서 **고유한 이름**을 가져야 합니다.
    *   **객체 (Object)**: 실제 데이터 파일입니다.
    *   **키 (Key)**: 객체의 이름이며, 파일의 **경로 역할**을 합니다.
*   **성능 지표**:
    *   **내구성 (Durability)**: 파일을 잃어버리지 않을 확률로, S3 Standard는 **99.999999999% (11개의 9)**를 제공합니다.
    *   **가용성 (Availability)**: 필요할 때 즉시 사용할 수 있는 능력으로, Standard 기준 **99.99%**입니다.
*   **정적 웹 호스팅**: 버킷의 퍼블릭 액세스를 허용하고 `index.html`을 업로드하여 웹 사이트로 활용 가능합니다.

### **3. AWS CLI 및 실무 명령어**
*   **기본 규칙**: `aws s3 cp [출발지] [도착지]` 형식을 사용합니다.
*   **주요 명령어**:
    *   `aws s3 ls`: 버킷 목록 확인.
    *   `aws s3 cp test.log s3://버킷명/`: 단일 파일 업로드.
    *   `aws s3 cp s3://버킷명/ ./ --recursive`: 버킷 전체 내용을 현재 디렉터리로 다운로드.
*   **핵심 옵션**: 디렉터리(폴더) 단위 작업을 할 때는 반드시 **`--recursive`**를 붙여야 합니다.
*   **경로**: **`./`**는 현재 위치한 디렉터리를 의미합니다.

### **4. 모니터링 및 자동화 (CloudWatch & SNS)**
*   **CloudWatch**: AWS의 "눈" 역할을 하는 모니터링 서비스로 **지표(Metrics), 로그(Logs), 경보(Alarm), 대시보드** 기능을 제공합니다.
*   **세부 모니터링**: 활성화 시 모니터링 주기가 5분에서 **1분**으로 단축됩니다.
*   **SNS (Simple Notification Service)**: CloudWatch 경보 발생 시 관리자에게 **이메일 알림**을 보내는 서비스입니다.
*   **자동 작업**: 경보 임계치(예: CPU 30% 초과) 도달 시 인스턴스를 **재부팅, 중지, 종료**하도록 자동 설정할 수 있습니다.
*   **stress-ng**: 인위적으로 부하를 발생시켜 CloudWatch 경보가 작동하는지 테스트하는 도구입니다.

### **5. 보안 및 정책 (Policy)**
*   **보안 그룹 (SG)**: 인스턴스 단위의 가상 **방화벽**으로, 허용할 포트(SSH: 22, HTTP: 80 등)와 IP를 설정합니다.
*   **버킷 정책**: JSON 형식으로 작성하며, 누가 어떤 객체에 접근할 수 있는지 정의합니다.
*   **Allow vs Deny**: 명시적인 **거부(Deny)**는 모든 허용(Allow)보다 우선하여 적용됩니다.
*   **IP 제어**: `Condition` 절의 `IpAddress`와 `aws:SourceIp`를 사용하여 특정 IP 대역만 접근을 허용하거나 차단할 수 있습니다.
